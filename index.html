GT Movies Store

Project Overview

GT Movies Store is a full-stack Django web application that allows users to browse a movie catalog, search for movies, create an account, write reviews, manage a shopping cart, purchase movies, and view their previous orders.

The application also provides an administrative interface through Django Admin. Administrators can manage users, movies, reviews, orders, and purchase items.

For the additional project requirement, I extended the review system with an inappropriate-review reporting feature. A logged-in user can report another user's review. Once reported, the review is removed from public display but remains stored in the database for an administrator to inspect.

Technology Stack

Python and Django were used for the application's server-side logic. HTML, CSS, and Bootstrap were used for the user interface. The project used MySQL during local development and SQLite for the deployed PythonAnywhere environment. Git and GitHub were used for version control and deployment.

Features and User Stories

  • User Story 1 — About: The application contains an About page describing the Movies Store.
  • User Story 2 — Sign Up: New users can create an account using Django's authentication system.
  • User Story 3 — Login and Logout: Registered users can log in, maintain an authenticated session, and log out.
  • User Story 4 — Movie Catalog: Users can browse movies stored in the application's database.
  • User Story 5 — Movie Search: Users can search the movie catalog by movie name.
  • User Story 6 — Add to Cart: Users can select a quantity and add a movie to their shopping cart.
  • User Story 7 — View Cart: The shopping cart displays the selected movies, quantities, prices, and total cost.
  • User Story 8 — Clear Cart: Users can remove all movies from the shopping cart.
  • User Story 9 — Create Review: Authenticated users can write a movie review.
  • User Story 10 — View Reviews: Movie detail pages display the public reviews for that movie.
  • User Story 11 — Edit Review: A review author can edit their own review.
  • User Story 12 — Delete Review: A review author can delete their own review.
  • User Story 13 — Purchase: An authenticated user can purchase the movies stored in their cart.
  • User Story 14 — Order History: Authenticated users can view their previous orders and the items belonging to each order.
  • User Story 15 — Deployment: GT Movies Store is deployed publicly using PythonAnywhere.
  • User Story 16 — Responsive Interface: Bootstrap responsive components allow the application to work at desktop and smaller browser sizes.
  • User Story 17 — Admin Users: Administrators can manage user accounts through Django Admin.
  • User Story 18 — Admin Movies: Administrators can create, view, update, delete, and search movie records.
  • User Story 19 — Admin Reviews: Administrators can manage reviews and inspect their reporting status.
  • User Story 20 — Admin Orders: Administrators can manage Order and Item records.
  • User Story 21 — Report Review: Authenticated users can report reviews created by another user. Reported reviews disappear from public view but remain stored for administrative review.

Development Process

I developed GT Movies Store by working through Django 5 for the Impatient, Second Edition. Instead of building the finished application all at once, each chapter introduced another Django concept and extended the same Movies Store project.

Chapters 1–2 — Django Setup and Project Structure

I first created the Django project and learned how requests move through Django's Model-View-Template architecture. I created the Home application, added Home and About routes, and learned how project-level URL configuration connects to an application's URLs, views, and templates.

Chapter 3 — Shared Templates and Styling

I created a reusable base.html template containing Bootstrap, the navigation bar, custom CSS, the site logo, and footer. Template inheritance allowed the rest of the application to share one consistent layout.

During this section, I also had to debug broken Bootstrap links and CSS classes that had been accidentally split across multiple lines. That helped me understand how small HTML formatting problems can affect the layout of an entire site.

Chapter 4 — Movies with Temporary Data

I created the Movies application and initially stored movie information in a Python list. I created the movie catalog and individual movie detail routes. This allowed me to understand Django URLs, views, templates, and URL parameters before adding a database.

Chapters 5–6 — Models, Migrations, and QuerySets

I created the Movie model and learned how model fields become database columns. I used makemigrations and migrate, installed Pillow for movie image uploads, created a superuser, and added the Movie model to Django Admin.

I then removed the temporary Python movie list and replaced it with database queries such as Movie.objects.all(). Movie search was implemented using the name__icontains QuerySet lookup.

Chapter 7 — Database Configuration

I learned more about the database layer and customized Django Admin so movies could be ordered and searched by name. I also followed the textbook's instructions for configuring MySQL in my local development environment.

This step required debugging database connection and configuration problems, including creating the actual Movies Store database before Django could connect to it.

Chapter 8 — Authentication

I created the Accounts application and implemented user signup, login, and logout using Django's built-in authentication system.

I customized Django's UserCreationForm so the signup fields used Bootstrap styling and created custom error output for invalid signup information. Authentication also allowed the navigation bar to display different options depending on whether the current user was logged in.

Chapter 9 — Review CRUD

I created the Review model and connected reviews to both Movies and Users with foreign keys. I then implemented Create, Read, Update, and Delete functionality.

This section also taught me about authorization. The application does not only hide Edit and Delete buttons; the Django views verify that the current user actually owns a review before allowing those operations.

Chapter 10 — Sessions and the Shopping Cart

I created the Cart application and used Django sessions to maintain a user's shopping cart between requests. Movie IDs and quantities are stored in request.session['cart'].

I implemented adding movies, displaying quantities, calculating totals, and clearing the cart. This helped me understand the difference between temporary session state and permanent database records.

Chapters 11–12 — Orders and Purchases

I created the Order and Item models so completed purchases could be stored permanently. An Order belongs to a user, while Items store the movie, quantity, and price associated with that purchase.

I then connected those models to the shopping cart. Completing a purchase creates an Order and its Item records, clears the session cart, and produces a purchase confirmation. The Orders page allows the current user to view their own purchase history.

Chapter 13 — GitHub and PythonAnywhere Deployment

The final textbook chapter moved the project from my local development environment to the public internet. I used Git and GitHub to version the project and transfer the code to PythonAnywhere.

Deployment required additional troubleshooting. My original project repository was hosted through Georgia Tech's GitHub Enterprise server, which PythonAnywhere could not access from my account. I created a standard GitHub repository for deployment and worked through Git authentication and repository configuration.

On PythonAnywhere I configured the virtual environment, WSGI application, allowed hosts, migrations, static files, and media files.

My local environment used MySQL, but MySQL was not available through my PythonAnywhere hosting plan, so the deployed version uses SQLite. I also configured STATIC_ROOT, ran collectstatic, and configured the PythonAnywhere static and media mappings.

Additional Requirement — Reporting Reviews

After completing the textbook application, I added the project-specific review reporting requirement.

I added a reported Boolean field to the Review model, created a reporting URL and Django view, and updated the movie-detail template so a logged-in user can report another user's review.

The public movie view filters out reviews where reported=True. This means an inappropriate review disappears for normal users without being permanently deleted. Administrators can still see the review and its reported status in Django Admin.

I also added a server-side ownership check so a user cannot bypass the interface and report their own review.

What I Learned

The biggest lesson from this project was seeing how Django's separate concepts combine into one application. Early in the project, URLs, views, templates, models, migrations, authentication, sessions, and deployment felt unrelated. By the end, I could see how they form one request and data flow.

The textbook's progression was helpful because each feature depended on something I had already built. Temporary movie data became database-backed models. Authentication made user-owned reviews possible. Sessions created a temporary cart, and Order and Item models made those purchases permanent.

I also learned how important debugging is in web development. Problems I worked through included Django template tags being split across lines, model and migration mismatches, MySQL configuration, Python version differences, GitHub authentication, static file configuration, and differences between local and hosted environments.
