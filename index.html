View Project

GT Movies Store

Project Overview

GT Movies Store is a Django website where users can browse movies, search for movies, create an account, write reviews, add movies to a shopping cart, make purchases, and look at their previous orders.

The project also uses Django Admin. An administrator can manage users, movies, reviews, orders, and the items that belong to each order.

I also added a review reporting feature for the additional project requirement. A logged-in user can report a review written by another user. Once the review is reported, it no longer shows on the public movie page, but it is still stored in the database so an administrator can see it.

Technologies Used

Python, Django, HTML, CSS, Bootstrap, MySQL, SQLite, Git, GitHub, and PythonAnywhere.

Live Application: Launch GT Movies Store

Main Features

  • About Page: Users can read information about the Movies Store.
  • User Accounts: Users can sign up, log in, and log out.
  • Movies: Users can browse movies that are stored in the database and open a page for each movie.
  • Search: Users can search for a movie by its name.
  • Shopping Cart: Users can choose a quantity, add movies to the cart, see the total, and clear the cart.
  • Reviews: Logged-in users can write reviews. Users can also edit or delete reviews that they wrote themselves.
  • Purchases: Logged-in users can purchase the movies currently in their cart.
  • Order History: Users can see orders they have made before and the movies included in those orders.
  • Responsive Design: The site uses Bootstrap so the layout can adjust to smaller screen sizes.
  • Deployment: The website is deployed online using PythonAnywhere.
  • Admin: Django Admin can be used to manage users, movies, reviews, orders, and items.
  • Review Reporting: A logged-in user can report somebody else's review. Reported reviews are hidden from the public movie page but are still available to the administrator.

Development Process

I built GT Movies Store while working through Django 5 for the Impatient, Second Edition. The project started out pretty simple, and each chapter added another part of the application. This made it easier for me to understand what each Django feature was doing before everything was connected together.

Chapters 1-2: Setting Up Django

I started by creating the Django project and learning the basic project structure. I made the Home app and created the Home and About pages.

This was where I first worked with URLs, views, and templates and started to understand how a request moves through a Django application.

Chapter 3: Templates and Styling

I created a shared base.html file so the pages could use the same navigation bar, footer, Bootstrap setup, and CSS.

I also worked with static files and images. I had to fix a few layout and template problems when some HTML and Django template code had been split across different lines.

Chapter 4: Movies App

I created the Movies app and first used a normal Python list to hold the movie information.

I made the movie list page and individual movie pages. This helped me get used to passing information from a view into a template before adding the database.

Chapters 5-6: Models and the Database

I created the Movie model and learned how Django migrations turn model changes into database changes. I also installed Pillow so movies could have uploaded images.

After that, I stopped using the temporary Python movie list and started loading the movie information from the database with Django QuerySets.

I also added the movie search feature using name__icontains.

Chapter 7: Database Setup and Admin

I set up MySQL for my local version of the project. This part took some troubleshooting because the database needed to be created and configured correctly before Django could connect to it.

I also worked more with Django Admin and made it possible to search and organize movies from the admin page.

Chapter 8: User Accounts

I created the Accounts app and added signup, login, and logout.

I used Django's built-in authentication system and customized the signup form so it matched the rest of the site better. I also changed the navigation bar so different options show depending on whether the user is logged in.

Chapter 9: Reviews

I created the Review model and connected reviews to both a movie and a user.

I then added the ability to create, view, edit, and delete reviews. I also added checks so users can only edit or delete reviews that belong to them.

Chapter 10: Shopping Cart

I created the Cart app and used Django sessions to store the movies and quantities in a user's cart.

I added the ability to put movies in the cart, choose a quantity, calculate the total, view the cart, and clear everything from it.

This part helped me understand the difference between temporary information stored in a session and information that is saved permanently in the database.

Chapters 11-12: Purchases and Orders

I created the Order and Item models so purchases could be saved permanently instead of only existing in the shopping cart.

When a user makes a purchase, the application creates an Order and its Item records. The cart is then cleared. The user can later open the Orders page to see what they purchased.

Chapter 13: Deployment

I used Git and GitHub to move the project to PythonAnywhere so the site could be available online.

I had to set up the Python environment, WSGI file, allowed hosts, migrations, static files, and media files on PythonAnywhere.

My local version uses MySQL. The deployed version uses SQLite because MySQL was not available with the PythonAnywhere account I was using.

I also ran into issues with GitHub access, static files, and differences between my local computer and the server. Fixing those problems gave me a better understanding of what is different between developing a site locally and actually deploying it.

Review Reporting Feature

After finishing the main project, I added the review reporting feature that was required for the assignment.

I added a reported field to the Review model. I also created a URL and view for reporting a review and added a Report button to the movie page.

The movie page only displays reviews that have not been reported. A reported review stays in the database and can still be seen in Django Admin.

I also added a check on the server side so users cannot report their own reviews.

What I Learned

The biggest thing I learned from this project was how all the parts of Django work together. At the start, URLs, views, templates, models, authentication, and sessions felt like separate topics. By the end of the project, I had a much better idea of how they connect to build one application.

I also got a lot more experience debugging. Some of the problems I worked through involved template syntax, database setup, migrations, login and logout code, GitHub authentication, static files, and deployment. Fixing those issues was one of the more useful parts of the project for me.
